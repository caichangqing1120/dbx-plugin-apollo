# Apollo Portal Console 持续修复与验证

日期：2026-10-20。开发版本：`0.1.3-rc.1`。原版基准仍为 Apollo v2.5.2，
`ed9785c87b390c22efece9ea7ec7eeab2d20a042`。

**全页面、全弹窗及全部条件状态的 1:1 门禁仍为 FAIL。** 本轮修复有独立的聚焦证据，
不能据此把其余历史差异或真实部署验收标为完成。旧 `0.1.2` 源标签、安装包、审计和签名资产保留。

## 本轮修复

- 创建应用、应用设置、创建集群和创建 Namespace 改用独立编写的表单列/控件列结构，
  恢复列内提示、静态 AppId、格式顺序、必填标记、源文案和应用管理员布局。
  不导入原版 HTML、Bootstrap、AngularJS 或控制器运行时。
- 集群创建成功后保留原版成功页面，不立即跳往配置页；成功表单不能再次提交，重新进入恢复新建表单。
  迟到的成功或失败响应不再跳转或污染其他页面；同页失败仍保留错误，不误报成功。
- 公共 Namespace 显示应用部门前缀，切换前缀保留名称、格式、备注和焦点。
  前缀只影响展示及原有 `appendNamespacePrefix` 参数，不在前端伪造服务端创建结果。
- 修复键盘误操作：Enter 在破坏性确认框的“取消”、原生选择器上不再转为提交；
  关闭的用户组合框用 Enter/方向键打开选项，不再误保存整个应用或授权表单。
- 切换语言时保留未保存的应用字段、负责人/管理员选择和配置编辑内容；移除的管理员标签不会被恢复。
  草稿仅在当前 UI 内存，不写 Host storage；导航/取消的既有清理规则不变。
- 配置区改为参与文档流的两列布局。长侧栏不再越过父容器和页脚，三种宿主宽度的左右栏位置保持不变。

## 证据质量与夹具修正

- 使用真实 DBX SDK sandbox 和实际 Go sidecar；后端只连接自建 loopback 夹具，账号为固定假数据。
- 原版集群前端使用 OpenAPI controller 路径，插件使用的 Portal controller 路径也确实存在。
  对照 pinned `ClusterService.js` 及两个 Java controller 后，仅补齐夹具中精确缺失的 OpenAPI POST，
  检查路径/payload AppId 一致并回读真实夹具状态；未知路径仍为 404，未改插件 API 来迁就夹具。
- 共享浏览器窗口曾出现逻辑 viewport 与实际窗口尺寸不同，右侧点击未被投递。比较脚本强制刷新
  owned viewport；不采用 force-click，也不注入原版 UI 状态来制造成功。
- 导航/触发时允许使用较高宿主窗口以完整展示长侧栏；最终成对截图均对齐到 1304×876。
  `masterNoPermissionDialog` 另记录 1180×1200 的原生触发宿主；不声称两侧所有触发上下文相同。
- 原版创建页的部门 placeholder 存在翻译初始化竞争；截图保留实际原版显示，不把该原版状态改写成插件行为。

## 仍未完成

- 顶栏搜索及部分单/多选器内部、失焦/动态查询等状态仍与原版不同。
- 其他管理页表格、文案/按钮/图标、预览/编辑器、比较/同步后续步骤及部分删除流程仍有历史差异。
- 本轮普通表单控件和指定提示通过，不代表四个页面全部状态或 24 个页面整体像素通过。
- pinned 原版中无调用路径的旧声明及通用模板继续标为 source-only，不伪造运行结果。
- 未连接真实 Apollo，未执行生产数据变更；原生桌面安装、Secret Store/重启、真实权限持久化和文件保存仍未验收。
